## 2. 清晰度才是正确的尺（不是像素数）

| 材料 | 像素 | 拉普拉斯方差 | 实际 |
|---|---|---|---|
| 达标练习 A | 1260×907 | **7382** | 电子屏摄图，全场最清晰之一 |
| 达标练习 B | 1250×881 | **9660** | 同上 |
| 数学作业 | 1080×1919 | **142** | 手机拍照 |

按像素数 A/B 只有 A4@300DPI 的 13%，会被判"必须预处理"；按清晰度它们比照片锐 **52 倍**，
任何像素级增强都是伤害。⇒ 清洗按清晰度分档（阈值 1500），不按分辨率。

## 3. 清洗管线：一轮把三条坏尺打回炉

**结论：`geo_only`（灰度 + 纠偏 + 裁边，不动像素）是唯一在所有材料上都不帮倒忙的档位。**
自动分档对清晰屏摄图正好选中它。

| 档位 | 屏摄图 A 清晰度 | 判定 |
|---|---|---|
| geo_only | 7382 → **8813** | ✓ |
| geo+denoise | 7382 → 2609 | ✗ 清晰度腰斩 |
| full（PRD 默认 8 步） | 7382 → **257** | ✗ 掉 96% |
| full+binary | 7382 → 1058 | ✗ |

**过程中我自己造了三把坏尺，全部作废并记录**（这类错误的代价是"把正常当 bug 去修"）：

1. **拿 OCR 字数当清洗判据** —— 15 个档位没有一个让 OCR 变好。但清洗是给**打印**用的，
   不是给 OCR 用的；RapidOCR 内部本来就有预处理。尺子问错了问题。
2. **`ink_retention` 用绝对墨迹像素数** —— 归一化放大 1.82 倍后算出 **413%** 的荒谬值。
   改成密度后又发现 CLAHE 会改变 OTSU 阈值本身，跨处理比"墨迹量"得到 120~143%，
   量的仍是阈值漂移而不是内容守恒。
3. 最终改用 **`crop_safety`**：同一张图、同一阈值下，量「裁框之外的边缘带还剩多少墨」。
   实测三份材料都是 **0.00%** ⇒ 裁边不切内容，这才是可证的结论。

> 顺带纠正一次误判：屏摄图裁边后 OCR 少读 9 个字（842→833），我一度判定"裁边吃掉了左侧
> 竖排装订栏"。用同图同阈值复测，绝对墨迹保留 99.71%、边缘带残留 0.00% —— **裁边没吃内容**，
> 那 9 个字是 OCR 对版面上下文变化的自身抖动（±5%）。

## 5. Windows 环境坑（都会咬人，已写进代码注释）

1. **`cv2.imread()` 读不了中文路径**，返回 `None` 且不抛异常 → 全仓库统一用 `app/parsers/image.cv_imread`（`np.fromfile` + `imdecode`）。写文件同理用 `imencode` + `tofile`。
2. **控制台 GBK 编码**，`✓ ✗` 与部分中文直接 `UnicodeEncodeError` → 脚本开头 `sys.stdout.reconfigure(encoding="utf-8")`。
3. `sys.argv[1]` 缺省时抛 `IndexError` 而不是 falsy。

## 7. 本轮新增的坑（都已进代码注释或测试）

1. **Python 通用换行模式会毁掉 JS 源码**。用 `open(p).read()` 改 HTML 时，JS 里的 `'\n'` 转义序列被当成真实换行，写回变成跨行字符串 → 整段 `<script>` 静默不执行，页面看起来"功能全没了"且没有任何提示。修法：读写文本文件一律 `newline=''`；并加 `tests/check_web_js.py` 把内联 JS 抽出来跑 `node --check`（该闸门已用注入缺陷验证过确实会 FAIL）。
2. **批量字符串替换必须核对命中数**。我用一个不匹配的字符串做 `replace`，替换了 0 处却打印"替换 12 处"，导致后续误判"改了但没生效"。
3. **`UnboundLocalError`：在赋值前引用局部变量**。给 relayout 加标题回填时把 `title` 用在了定义之前，直接把验收打成 0/10。
4. **测试自己把两次下载写到同一个文件名**（`var/acc/{tid}.pdf`），于是"对比省墨前后"实际是把同一个文件量了两遍，看起来像"开关无效"。修：`download(tid, tag)`。
5. **量错位置**：判"省墨有没有效"要量 PDF 里**内嵌的那张图**，不是整页渲染——页边距的白底会把差异稀释掉（整页两边都 91.1%）。
6. **判据要能证明开关起作用**。`w1 >= w0 - 0.02` 这种写法，开关完全无效也会"通过"（假绿）。改成 `w1 > w0 + 0.10`。
7. **PyMuPDF `insert_text` 默认 Helvetica，写不进中文**，会静默变成 `·3· ········`。压测夹具必须用 `fontname="china-s"`，并且**先自证内容真的写进了 PDF**再去测产品。
8. **一次我编造了根因**：断言"缓存键碰撞导致省墨无效"，实际两个缓存文件名根本不冲突。教训：没验证的因果推断不能写进注释——那条假注释后来被删掉了。

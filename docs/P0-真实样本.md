## 3. 三个在合成样本上永远看不到的问题

### 3.1 双栏排版把题目顺序打乱了（新发现，影响 P3）
`第三单元达标练习题A.jpeg` 是左右两栏的语文卷。RapidOCR 读出 87 行、842 字、置信度 0.93，**但行的先后顺序是跨栏穿插的**——左栏第一题和右栏第三题交替出现。
> 摘录：`3.选择合适的动词，填入校园生活故事中…` 后面紧跟 `测评卷`、`5·3天天练小学语文二年级上册`、`①滚 丢 ③拍`

⇒ **P3 之前必须加一步「分栏检测 + 按栏重排」**，否则切题引擎拿到的输入顺序就是错的，规则写得再好也切不对。这是工作流的一个新增阶段。

**已实现并用真实数据验证**（`src/layout.mjs` + `tests/layout.mjs` + `tools/validate-layout.mjs`）：

| 样本 | 检出栏数 | 右栏首行（重排后） | 说明 |
|---|---|---|---|
| 达标练习 A | 2 ✓ | `3.选择合适的动词，填入校园生活故事中。（10分）` | 原始 OCR 里它是**第 0 行**，穿插问题消除 |
| 达标练习 B | 2 ✓ | `3.莱叶上的小洞是（）咬的…` | 左栏首行 `2.根据所学知识完成对话` 与页面实际一致（此页是第 3-4 页，第 1 题在上一张） |

实现过程中真实数据连续打穿四次，每一次都留下了回归测试：

1. **顺序错**：先 `groupLines` 再 `detectColumns` ⇒ 双栏同水平线的文字被缝成横跨全页的"行"，间隙消失，**必然漏检**。正确顺序是**先用原始碎片框找栏，再在栏内合并行**。回归用例：`先合并成整行再分栏必然漏检`。
2. **桶宽写死**：固定 20px 直方图桶把 600 宽页面上 50px 的三栏间隙量化成"不存在"，三栏一律读成单栏。改为随内容粒度自适应（取条目宽度中位数）。
3. **装订栏误判**：真实试卷左侧的竖排`学校/班级/姓名/学号`只有 2–3 个框，却把整页判成 3 栏。加入「内容占比 <10% 的边栏并入相邻栏」过滤。回归用例：`左侧装订栏不该让整页误判成三栏`。
4. **通栏过度抽取**：只要求"跨过第一条栏界"会把普通长行误判为通栏并抽离正文——B 卷的`六、大作文`题头被错排到全文首行。收紧为「跨过栏界 + 跨过页面中线 + 自身 ≥40% 页宽」，且**只有位于所有正文之上的通栏元素才前置**，嵌在正文中的留在原栏。

**度量本身也错过一次**：把大题号（一、二、…）和小题号（1. 2. …）混在一条数轴上数"回跳"，会把 `二、… 1.` 这种正常结构误记成乱序。已分成两条序列各自计数。

**诚实边界**：以上只在**二年级双栏语文卷**这 2 份上验证过，样本 n=2。八年级的密排版面、图文混排、几何图跨栏，都还没测。

### 3.2 「分辨率低 = 不可读」是错的（我的判据被证伪）
`triage.mjs` 按「相对 A4@300DPI 的像素比」给两张语文卷判了「偏低：预处理是前置必需项」（13%）。
实际它们是**电子屏摄图**：1260×907，无模糊、无噪点、无畸变，OCR 置信度 0.93。
⇒ 分辨率只是**照片**的代理指标。对截图/扫描件，真正要量的是清晰度与畸变，不是像素数。判据要按输入类别分开。

### 3.3 页面尺寸不统一，重排必须先归一化
真实页面：595×907pt、595×906pt、595×888pt、595×858pt（A4 是 595×842pt）、841×653pt（横向）、370×287pt（半页）。
⇒ 「任意文档 → 统一 A4」不是排版美化，是硬前提；且**横竖混排**要能分开处理。

## 4. 本轮修掉的四个 bug（都有测试或复现记录）

1. **pdf.js viewport 用错**（`P0-结论.md §3 读数作废 2` 的根因）：`getViewport({scale})` 的 `scale` 是倍率不是 DPI，默认 viewport 已是 72 DPI。正确写法 `page.getViewport({ scale: dpi / 72 })`。修正后真实页渲染为 1653×2519 px（595×907pt @200DPI 应为 1653×2519），**吻合**。
2. **multipart 解析器静默丢文件**：`/api/save-render` 收了 5 张图返回「没收到文件」。两处 bug——① `(field || name)` 把表单字段名 `blob` 当文件名，扩展名过滤于是全丢；② 头部按 latin1 解码，中文文件名被毁成 `h____1.pdf_p1.jpg`。已抽成 `tools/multipart.mjs` + `tools/test-multipart.mjs`（含中文名、路径穿越、无 boundary、空表单 4 个反例）。
3. **`ocr_rapid.py` 拿错 ground truth**：真实语文卷被拿去和合成物理卷的原文比，得出 `sim=5.8%` 的废数。已改为 ground truth 可选，无匹配时 `sim` 报 `null` 而不是假数字。
4. **pdf.js 渲染在 Qoder 内置浏览器里永久挂起**（新发现，影响测试方法）：同一份 PDF、同一段代码，`page.render()` 在内置浏览器（Electron / Chrome 150 内核）里 20 秒不返回，`getTextContent()` 却正常；canvas 本身可用；换同域 worker、换 `disableWorker` 都无效。**在真 Chrome 里 266 ms 完成**。
   ⇒ 凡是涉及 pdf.js 渲染的验证，必须在真 Chrome（chrome-devtools MCP）里跑，不能在内嵌 webview 里跑。否则会误判成"产品做不出来"。

## 5. 对 WORKFLOW 的修改

- **P3 拆成两步**：P3a 版面结构化（分栏检测、按栏重排、页面归一化）→ P3b 切题。原 P3 把这两件事混做，会在双栏卷上直接失败。
- **P2 的判据按输入类别分开**：照片类看模糊/畸变，截图类看压缩与字体渲染，不能共用一个像素阈值。
- **输入分类新增一类**：`手机拍的手写作业`（数学作业.jpeg）。它不属于「转成可作答试卷」，属于「批改孩子已做的作业」——是用户痛点④的另一半，且手写 OCR 是开源黑洞。**V1 明确不做，写进 README 的边界。**

## 6. 一个必须回给用户的观察

这批材料是**小学二年级**（语文：拼音、量词、古诗；数学：乘法口诀、`2×5`、`6个2相加`），而最初需求描述的是「娃上 8 年级」。
两者难度结构差别很大：八年级会有密排文本、几何图、函数图像、物理化学公式、分数与根式；二年级是田字格、拼音格、大留白、图为主。
⇒ 用这批材料测出来的结论（尤其是版面与切题）**不能直接外推到八年级**。需要补一批真实的八年级材料再判一次。

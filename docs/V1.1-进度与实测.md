## 1. 切题（extractor）

### 1.1 真实材料结果（7 份，含 5 份无文本层扫描件）

| 材料（脱敏代号） | 类型 | 大题 | 切出题目 | 编号行 | **重号** | 过滤水印行 | 栏目行 |
|---|---|---|---|---|---|---|---|
| 文字卷 A | 文本层 | 1 | 8 | 8 | 0 | 0 | 0 |
| 文字卷 B（英文） | 文本层 | 4 | 9 | 8 | 0 | 0 | 0 |
| 扫描卷 C（周末作业） | OCR | 3 | 8 | 5 | 0 | 13 | 4 |
| 扫描卷 D（单元练习 8 页） | OCR | 10 | 35 | 34 | 0 | 27 | 18 |
| 扫描卷 E（达标练习） | OCR | 7 | 25 | 20 | 0 | 9 | 0 |
| 扫描卷 F（同 E 另一份） | OCR | 7 | 25 | 20 | 0 | 9 | 0 |
| 扫描卷 G（教辅按天） | OCR | 3 | 12 | 12 | 0 | 11 | 6 |

**重号 0** 是这一节的核心结论。上一版这里报 14–20 个重号，看着像"切题切坏了"，
实际是**分段判据不对**：真实卷的大题名根本不写「一、选择题」。

### 1.2 PRD F11 正确率（`tests/run_f11.py`）

度量用的尺**不复用产品里的正则**，`tests/run_f11.py` 自己写了一把 `NUMBERED_RE`
（行首数字+顿号/句点且后面还有内容），否则实现漏掉的形态尺也会漏掉，等于自己给自己打分。

```
合计：编号行 106  命中 106  题号召回率 100.0%（严格口径 100.0%）
      切出题目 122  其中无正文碎片 2（1.6%，全部标 needs_review）
      需人工校对 62（50.8%）
PRD F11（≥80%）→ PASS
```

两个口径都报：宽口径允许"一行被拆成多题"时按前缀算命中，严格口径只认整行相等。
这次两者相同（106/106），说明没有靠宽松匹配凑数。

`需人工校对 50.8%` 偏高，原因是扫描卷 OCR 断行把题干截短（"…它的特点是一端指"），
置信度上不去。这是**如实标注**而不是漏判——PRD F11 允许"可人工校对"。

### 1.3 这一轮修掉的 6 个真错

| 症状 | 根因 | 修法 |
|---|---|---|
| 整卷只认出 1–2 个大题，报 14–20 个重号 | 大题名不带"题"字（「三、公园畅游指南」「六、随着无人驾驶技术的发展…」） | 判据换成**序号递增**（`n >= expect_no`），关键词表退化为加分项 |
| 「第2天 画校园路线图[课时2]  拍照秒批」漏认分段 | 曾用「标题剩余长度 ≤24 才算分段」 | 删掉长度闸门，水印由 `_clean_title()` 洗；护栏只留"标题不带答题空位" |
| 扫描水印变成题目 | 每页都有「夸克扫描王/极速扫描/拍照秒批/视频讲解」+ 页码 | `_is_noise()` 过滤，落进 `dropped_noise` 可审计 |
| 题号 2 凭空消失 | 页码正则 `^\d+[.。]?$` 把裸题号「2.」当页码丢了 | 页码必须两侧都有分隔符（`·38·`「。26。」） |
| 英文卷 Section 一个没认出 | `SECTION_EN_RE` 分组错位，拿字母 A/B/C 去查关键词 | 用 `group(3)`（标题正文） |
| 卷名变成第 1 道"填空题" | 首行没题号就被当题干 | 卷名提升：无题号+无空位+≤30 字+后面有带号题 → 当标题 |

## 2. 批改（grading）

### 2.1 判分口径

| 题型 | 判法 | 判不准时 |
|---|---|---|
| 选择 | 先比标号（A/B 或 ①②），再比选项正文 | — |
| 判断 | √/×/对/错/T/F/正确/错误 归一后精确匹配 | 写法认不出 → **待确认** |
| 填空 | NFKC、大小写、标点、空白、乘号统一；分数/小数/百分数/中文数字/中文分数按数值比；带单位（48个≡48）；`\|` 分隔多可接受答案 | 有空位没标准答案 → **待确认** |
| 问答 | 不自动判分，只给关键词重合提示（PRD 明确不计分） | 一律 **待确认** |

取向：**宁可少判对，不可判错为对**；但"有标准答案而写法不匹配"就是明确的错——
第一版把所有比不上的都标待确认，结果一份 20 题的卷子全是黄标，
家长复核成本比手工判卷还高，这不算兜底，算没做完。

### 2.2 F14 端到端（`tests/acceptance_v11.py`）

```
✓ F14 填空容错批改  分数等价√ 全半角√ 答错判错√ 问答不自动判√（得分 4.0/7.0，待确认 1.0）
```
覆盖：`1/2 ≡ 0.5 ≡ ０．５`、`二十四 ≡ 24`、`二分之一 ≡ 1/2`（分母在前）、
`48个 ≡ ４８`、选择题答"整条选项文本"、答错必须判错。

### 2.3 浏览器实测（真机 Chrome，不是接口自测）

`paper.html?paper=13`：填 7 题 → 刷新页面 → **草稿全部回来**（含单选、多空、问答、班级姓名）
→ 提交 → 得分 3/7、待确认 2 → 点标记人工改判 → 分数即时重算。

这一趟抓到一个纯单测抓不到的错：做题页单选框的 value 存的是**整条选项文本**
（"A. 四七二十八"），而标准答案只写 "A"，`_marker()` 解析不出字母前缀，
把对的判成错的。单测里我从来没构造过"字母+整条正文"这种作答。

## 3. 存储与接口

- SQLite 落在 `data/papers.db`（**不在 `var/`**：服务启动会整目录清空 `var/`，
  第一版把库放那儿，等于每次重启把孩子的作答和标准答案删干净）。
- 题目 uid = `q<rowid>`，家长校对改了题号/题型后标准答案不失联（有单测钉住）。
- 接口按 PRD §7.4 全部落地：`/api/papers/{id}/parse|questions|key|submissions|grade|export`。
  `{id}` 支持试卷号或任务号（惰性建档），前端不用学两套 ID。

## 5. 过程问题：尺自己也会骗人（三条，都值得单独记住）

1. **变异闸门报"某条缺陷没尺在量"，其实是闸门坏了。**
   `mutate_gate` 把失败行在 `→` 处截断后再和期望串匹配，凡是期望串带「→」的
   （如「无标准答案 → 待确认（反例）」）永远匹配不上 → 12 条里误报 2 条"没抓到"。
   单独手工复现才发现。**尺报错时先怀疑尺。**
2. **端口被上一轮没杀掉的服务占着。** 新起的 uvicorn 静默绑定失败，
   "跑新代码的验收"其实打在旧代码上——表现为改了没反应。
   现在 `/api/health` 带 `pid`，三个 HTTP 验收脚本都核对"回答我的是不是我起的那个"。
3. **夹具自己坏了会伪装成产品坏了。** V1.1 样本卷最初从 y=780 往上写，
   整页行序倒过来，题目串到大题里，F12/F14 报的全是假失败。
   现在造完样本先自证："第一行必须是卷名"，再让产品去读。

## 7. 第二轮返工（2026-10-18，用户四条要求）

### 7.1 校对模式独立成页（改 / 增 / 删 / 发布）

`web/proofread.html` 是给**上传者**用的，`web/paper.html` 只做题——
做题页现在没有任何编辑入口（浏览器实测：页面文本里找不到"校对这题 / 删除这题 / 题型"任何一处）。
**发布是收尾动作**：没发布（`status != published`）的卷子提交作答直接被后端拒（409），
验收里这条是显式断言的；发布时还会挡一道"既没题干又没配图"的空题。

接口：`PUT/POST/DELETE /api/papers/{id}/questions`、`POST /publish`、`POST /unpublish`。
加题/删题后 `ord` 与 `auto_no` 重排，但 **uid 不变**——已录的标准答案不会失联（有单测）。

### 7.2 前端改版

先查了 2026 年的公开规范再动手（8pt 栅格、单一主按钮、正文左对齐、
UI 元素对比度 ≥3:1 / 文字 ≥4.5:1、组内间距小于组间、状态不只靠颜色），
落进 `web/css/app.css` 的设计令牌（`--s1..--s8` 只允许 4/8/12/16/24/32/48）。
四页统一：上传 → 打印版 → 校对题目 → 在线做题，顶栏步骤条可跳转。
（⚠️ 这一行的顺序是**当时**抄错的版本，第 9 节已按用户口径改成 上传 → 校对 → 做题 → 打印，
　并把这个"每页各抄一份数组"的结构收成了单一来源。留着这行是为了记住它错在哪。）

原来的问题很实在：做题页复用了预览页的 `.grid`（`150px 1fr 250px` 三栏），
左栏被压成 150px，"班级""姓名"两个字竖排换行、按钮挤成一列。

**第二轮改版（同一天，用户看了第一版改版后再次打回）**

用户第二轮的截图是**完全没有样式的裸 HTML**。根因不是配色：我把样式表写成绝对路径
`/css/app.css`，而他双击 `web/index.html` 用 `file://` 打开 → 浏览器去磁盘根
`C:/css/app.css` 找 → 找不到 → 整页样式全丢。所以"黑不溜秋"其实是路径 bug，
不是设计没做。两条一起修：

1. 四个页面的样式与接口**一律相对路径**（`css/app.css`、`api/...`、`preview.html?...`）。
2. `file://` 打开时页顶明确提示"只能看界面，请先跑 `scripts\setup.ps1` 启动服务"，
   并把上传按钮禁掉——不能让人以为程序坏了。
3. 钉进门禁：`tests/check_web_js.py` 扫四页，出现 `href="/css/`、`src="/`、
   `fetch('/api/` 就 FAIL。**注入一次绝对路径验证过它真的会红**（还原后 rc=0）。

视觉本身也重做到了工具类产品的样子：顶栏 logo 标记 + 步骤条、居中大标题、
**蓝紫渐变的上传面板**（白色"选择文件"按钮 + 虚线内框 + 图标）、绿色勾信任条、
三种模式卡片、四步流程、页脚。四页改版后都用真机 Chrome 截图核对过（含 `file://` 一张）。

### 7.3 A3 横版对开（标准试卷样式）

`page_format = a4 | a3_spread | a4_2up`。**a3_spread 是 1:1 并排、不缩放**
（A3 长边正好 = 2×A4 宽），字号、行距、图都和单页一样；
`a4_2up` 才是原来那个 √2 缩印省纸模式——两个需求不同，各有一条反例测试钉住不串。

实现走"先按 A4 排版，再事后拼页"（`app/papers/spread.py`），
模式 A/B/C 共用同一份 A4 版面，不会出现"打印版和做题版行宽不一样"。
页码按 **A4 面数**：一张 A3 上同时有"第 1 页 / 共 2 页"和"第 2 页 / 共 2 页"，
测试拿 A4 版面对照，标签必须正好是 1..N。左侧密封线（学校/班级/姓名/学号竖排）+ 中线装订缝。

⚠️ 密封线第一版画在 21mm、左边距 20mm，虚线直接从题干上穿过去——
**是渲染成图片看了才发现的，纯代码检不出来**。现在整条落在页边距以内（14mm），
并补了一条读 `get_drawings()` 竖线坐标的几何断言。

### 7.4 题目配图不再丢

`app/extractor/figures.py`：每题在源页上占一个纵向区间，把区间栅格化后
**挖掉所有文字行的框**，剩下的墨就是图形；包围盒够大才认定有图，按 200DPI 裁成 PNG，
存 `data/figures/<paper>/`（不能放 `var/`，那里每次启动会被清空），
经 `/api/papers/{id}/figures/{name}` 出图。校对页可见可移除，做题页与模式 B/C 导出都会画。

两个坑：
- `spans_for_questions` 一开始用"整行相等"找题目对应的源行，但 `extract()` 会把题号剥掉
  （源行 `1. 看图…` → `source_lines` 只剩 `看图…`），结果一道图都裁不出来。比对前两边都得剥号。
- 面积阈值 2600pt²（≈51×51）会把**数轴、线段图这类又长又扁的图**整批判掉；
  降到 1200pt² 并保留"最长边 ≥42pt"，同时留反例：纯文字卷不许裁出废图。

## 8. 第三轮：网页上点一下就把服务拉起来（F17）

### 8.1 诉求与绕不过去的限制

用户的原话是「能不能我打开这个网页就自动启动这个服务啊，还要我手动去启用服务就很麻烦啊」，
随后自己给了退路：「或者你就在网页上加一个步骤，检测到没有启动服务，就给一个按钮」。

先把硬约束说清楚：**浏览器不允许网页启动本地进程**，这是所有浏览器的沙箱规则，
不是本项目偷懒。所以"页面里点个按钮就把 uvicorn 拉起来"必须借道操作系统的
**自定义协议**：注册 `panjuan://` → 网页把 `location.href` 指到这条 URI →
Windows 用注册好的命令执行 → 命令是 `wscript.exe start_hidden.vbs`（隐藏窗口，
不闪蓝框）→ vbs 调 `start.ps1 -NoBrowser` → 后台起 uvicorn。
注册全部写在 `HKCU\Software\Classes\panjuan`，不要管理员权限，`-Remove` 能撤干净。

### 8.2 探测方式：先测再写，不猜

`file://` 打开的页面能不能探到本机服务？实测（Chrome，本机，服务在跑）：

| 探法 | 结果 |
|---|---|
| `fetch('http://127.0.0.1:8000/api/health')` | **status 200**（file:// 到 localhost 没被跨域挡） |
| 同上，端口没人监听 | `TypeError: Failed to fetch` |
| `new Image()` 指向 /api/health | onerror（返回的不是图片，这条不能用） |

所以 fetch 成/败就是干净的"起没起"判据，不需要图片探针、也不需要给 API 加 CORS。
这条实测结论直接决定了 `js/gate.js` 的写法。

### 8.3 三种状态与实测经过

`web/js/gate.js` 挂在四个页面（相对路径），启动时探一次：

* 服务在跑 + 页面是 `http://` 打开的 → 什么都不显示；
* 服务在跑 + 页面是双击 HTML（`file://`）→ 顶部绿条，1.2 秒后自动切到正式地址
  （`file://` 下功能不全，没道理留在那儿）；
* 服务没跑 → 顶部橙条 + 「▶ 启动服务」+「手动方式」。

真机走了一遍：

1. 停服务后双击打开 `index.html` → 橙条出现，两个按钮都在（截图核对，样式来自 app.css）；
2. 点「▶ 启动服务」→ 文案变「正在启动…」，页面开始每秒重试健康检查；
3. 轮询期间从命令行 `start "" panjuan://start`（等价于用户在确认框点「打开」）→
   服务 4 秒起来 → 页面**自动跳到 `http://127.0.0.1:8000/index.html`**，门闸消失；
4. 服务已在跑时再双击 `index.html` → 绿条 + 自动跳转，同样落到正式地址。

**没验到的一段**：Chrome 那个"要打开 磐卷 PaperForge 吗"的确认框是浏览器原生 UI，

### 8.4 这一轮踩的坑（都已变成门禁）

* **注释没闭合吞掉整页**：给四个页面注入 `<script src="js/gate.js">` 时写了中文注释
  却漏了 `-->`，未闭合的注释把 script 标签连同 `<body>` 开标签一起吞了 —— 页面几乎空掉，
  浏览器一声不吭，而**当时所有闸门一路绿灯**。修法除了补 `-->`，
  更给 `tests/check_web_js.py` 加了三条：`<!--` 与 `-->` 必须成对、

* **外链 JS 是语法检查的盲区**：`check_web_js.py` 原来只 `node --check` 内联 `<script>`，
  `web/js/*.js` 从没进过。现在补上，并顺手禁掉 gate.js 里的 `innerHTML`
  （文案全是写死的，但"没有页面数据进 HTML"应该是结构保证而不是承诺）。
* **写死清单的修 BOM 工具**：`fix_ps1_bom.py` 的默认清单只有两个手写文件名，
  新增的 `install_startup.ps1` 不在里面 → 没自动加 BOM，中文 Windows 上直接语法错误。
  改成扫盘（`scripts/*.ps1` + 根目录 `*.ps1`）。
* **跨 shell 把 `\b` 变成退格符**：往 `check.bat` 插 `py -3.11 tests\break_webgate.py` 时，
  `\b` 落地成 `0x08`，路径变成 `tests<BS>reak_webgate.py`。0x08 是 ASCII，
  "必须纯 ASCII"那条检查照样放行，直到 cmd 报找不到文件。
  现在 `.bat/.vbs/.ps1` 一律禁止 `\t\r\n` 之外的控制字符。
* **注册表读写不靠猜**：`install_startup.ps1` 改用 .NET Registry API，
  写完立刻读回来核对（`(Default)` 值用 `$null` 取），对不上就报错退出——
  安全软件拦注册表写入是真实可能，不能只当成功。
* **判决放进退出码，别让调用方比对文本**：F17 一开始是"跑 `-Check` 拿输出、在 Python 里
  比对路径字符串"。这条路在中文文件夹名下会翻车（PowerShell 的输出过一遍代码页就成了乱码，
  比对结果看着像"指向别处"，其实是尺坏了）。改成 `-CheckThis`：
  0=已注册且指向本检出、2=没注册、3=注册在别处，测试只看退出码。
  三个判决都实测过（把注册表临时指到 `C:\fake\elsewhere\` 验 3，`-Remove` 后验 2，再注册回来验 0）。
  顺带把比对方式从 `-like "*路径*"` 换成 `Contains` —— 路径里出现 `[` `]` 时 `-like` 会按通配符解释。

## 9. 第四轮：流程顺序改对 + 预览"改了没反应"修好

用户两句话，都是硬伤：

> "你这个顺序是错误的：上传 → 校对 → 在线做题 → 打印成 PDF。在线做题我可以直接跳过，
>  直接去第四步。如果我做了，打印出来就是带我的答案的；如果我没做，打印出来就是空白卷；
>  如果我开了自动批改，那导出的就带自动批改的结果。"
> "而且你现在做的这个样式，为什么我切换了，左边的预览没有任何变化。"

### 9.1 顺序为什么会错，以及怎么让它错不了

根因不是"想错了"，是**同一份顺序抄了四遍**：每个页面各自有一份 `items=[...]` 数组，
`preview.html` 那份把「打印版」排在第 2 步。抄一遍就漂一次，四页互相打架，用户一眼看出来。

修法是**把顺序收成一处**：新增 `web/js/app.js`，步骤条只在那里定义
（上传 → 校对题目 → 在线做题 → 打印成 PDF），页面只用 `<body data-step="print">` 声明"我是第几步"。
配套三条门禁（`tests/check_web_js.py` 里的 `check_flow` / `check_canon_steps`）：

1. `js/app.js` 里的顺序必须等于口径；
2. 页面里再出现自己抄的步骤数组 → FAIL；
3. 流程页必须挂 `js/app.js` 并声明 `data-step`；首页那段"四步"文案也要同序。

`tests/break_webgate.py` 把这四条各打坏一次（换序、自己抄一份、不声明第几步、
首页文案写错），**四处全部变红**。

### 9.2 第 4 步「打印成 PDF」的三种内容

新增 `web/print.html`，旧的 `preview.html`（挂在第 2 步位置上的"打印版"页）退役删除。
内容三态由 `GET /api/papers/{id}/printable` 一次性给状态与理由：

| 内容 | 能选条件 | 不能选时页面写什么 |
|---|---|---|
| 空白卷 | 有题目即可（**没发布也能打**） | "还没识别到题目（先在第 2 步校对并发布）" |
| 我的答案 | 有作答记录 | "这份卷子还没人作答过：先去第 3 步做题，或改选「空白卷」" |
| 我的答案 + 自动批改 | 有作答 **且** 有标准答案 **且** 有批改结果 | "还没录标准答案：在做题页点「把我的作答存为标准答案」" |

不可用的选项**照样显示、radio 禁用、原因写在里面**——灰掉一个没有解释的按钮，
用户只会反复点它或者以为程序坏了。

### 9.3 "预览没变化"的真凶与结构性修法

先量再改（`tests/` 里那版探针，跑完删掉，判据已并进 F18）：
后端**其实是会重排的** —— A4 3 页 → A3 对开 2 页，图 hash 全变。所以问题全在前端与缓存：

1. 旧页面只在点「应用并重排」后才拉一次，而文案写着"改任何选项都会立刻重排" —— **话在骗人**；
   滑块连 `change` 都没挂，只改了右上角那几个小字。
2. 预览图 URL 一直是同一批 `preview_1.png`，`FileResponse` 又没带 `Cache-Control`，
   同名文件被浏览器拿缓存 → 就算重排了也看不见。

修法：

- **任何版式改动 450ms 防抖后自动** `PUT /api/papers/{id}/options` → 拉预览，不靠点按钮；
- 预览图文件名带上**内容哈希** `preview_<rev>_N.png`，
  rev = md5(mode + 作答号 + 版式 + 全部题目 + 标准答案)。
  不用自增计数是因为"忘了 bump"是常态：题目改一版、作答提一次、标准答案换一版……
  漏一处就退回"URL 一模一样 → 浏览器拿旧图 → 用户说没变"。哈希覆盖全部输入，忘了也变不了；
- 出图路由显式 `Cache-Control: no-store`；
- 前端 `seq` 计数丢弃乱序返回的旧响应，避免"改了 A 显示 B"。

### 9.4 F18 与它的三次自我打坏

`tests/acceptance_v11.py` 新增 F18（8 条 → 9 条 → **10 条**），判据全部读真实产物：

- 服务端发出去的 `js/app.js` 顺序 = 口径；三个流程页都挂它且没有自己抄的数组；
- 未作答的卷子：`preview?mode=answered` 必须 404，`printable` 必须给出带"作答"二字的理由；
- 同一份内容两次请求 revision **必须相同**（否则就是随机数假动作）；
- A4 → A3 对开：revision 变、`image_url` 变、页面几何从 595×842（竖）变到 1190×842（横）；
- 三种内容三份 PDF 大小互不相同；往问答题里塞一个验收专用串，
  **空白卷的文本层读不到它、带答案与批改版读得到**；只有批改版表头匹配 `得分\s*[0-9.]+\s*/`。
  （批改符号是矢量画的线，不在文本层里，所以不能拿 ✓/✗/△ 当判据 —— 差点就写了条读不到的尺。）

`tests/break_flowgate.py` 把这条链故意打坏三次：revision 换成随机数、
空白卷偷偷按 answered 渲染、版式存了但渲染不读 —— **F18 三次都红，且报的就是预期那一条**。
这个脚本要跑三遍完整验收（约 7 分钟），所以不进 `check.bat`，改到导出/预览逻辑时手动跑。

## 12. 第七轮：一张图不许切成两块（"你把应该一页的弄成多页了"）

用户发来一张截图：**第 3 题那一张"实践基地平面示意图"被裁成了左右两张**，
配的话是"你把应该一页的弄成多页了"。

根因不在裁图，在**挖字**这一步：为了让配图里不混题目文字，裁图前要把 OCR 读到的
文字行从墨迹里挖掉。可这类图**本来就带字**——"西瓜基地—葡萄基地—草莓基地"就是图里的

所以这一轮做的是"把我们自己挖开的缝补回去"，而不是再调裁图框。

### 12.1 补洞合并：只补"自己挖的洞"

`_bridge()` 在连通域之后跑，两块并成一张要同时满足三条：

| 判据 | 取值 | 它挡住的真实反例 |
| --- | --- | --- |
| 缝里被挖掉的文字面积占比 ≥ | 0.35 | 酒店疏散图 与"如遇火灾请勿乘电梯"框相隔 18pt，但缝里 hole 只占 0.24 → 是两张图，不并（实测没并） |
| 副轴重叠 ÷ 较矮那块 ≥ | 0.40 | 斜着不相干的两块 |
| 缝宽 ≤ 22pt **或** ≤ 1.5×较小那块边长 | 22 / 1.5 | 两个钟面隔 220pt（比值 2.8）→ 不并；图框上下两条边各只有 2pt 高、缝 18pt（比值 9）→ 只能靠绝对值并上 |

阈值不是拍的：先把四份真实卷里**每一对碎片的三个数**全打出来（`var/_diag_runs.py`
那张读数表），"该并的"和"不该并的"两种样本同时在场，再定线。
判据实现前先看数、判定函数单独写（`_axis_measure` 只测量、`_can_bridge` 才判定），
是为了不再犯"判据和驱动它的读数搅在一起"的旧错。

用户那张图实测：两块缝 14.9pt、hole 0.61、重叠 1.00 → 并成一张 ✓。

### 12.2 三种"根本不是图"的东西

* **文字残影**（`_is_text_residual`）：OCR 行框和字实际印的位置能差**整整一行高**
  （真实卷：框在 y 623–640，字在 638–652），于是笔画留在原地被膨胀半径连成 242×14 的"图"。
  判据四条全中才砍：落在某行文字框内（容差=一行高）、高 ≤16pt、宽 ≥60pt、
  **框内最长连续水平墨 <18pt**。最后一条是数轴、线段图、带连线表格的保命符——
  图里的横线是几十上百 pt 一根，汉字笔画最多一个字宽。
* **装订栏 / 侧边栏**（`_is_margin_strip`）：贴物理页边 45pt 以内、宽 ≤60pt、高 ≥1.5×宽。
  实测拦下 36×199、18×117、52×109、40×98、34×116、60×184 六种条，
  同卷真图（48×73 指南针、239×69 平面图、195×169 房屋图）一张没误杀。
* **页上家具**（`_is_furniture`）：同一个框在**另一页的同一位置**又出现（±12pt、尺寸差 <15%）
  且贴页边 → 每页都印的页眉 logo / 页脚"夸克扫描王"二维码。三页卷上一次性砍掉 3 张。

### 12.3 缺的那一行标签要吸回来，但四条判据缺一不可

图顶那行字被挖掉后，裁出的图会把第一行切成半截（实测 y0=424，字印在 412–428）。
`_absorb_label_rows()` 允许把**紧贴图边**的那行吸进裁图范围，四条同时成立：
贴边 ≤8pt、整行落在图的横向范围内（只放宽 6pt）、这行至少图宽的七成、
不是区间第一行（第一行必然是题干）。
四份卷全跑下来只吸了两处，两处都是该吸的（实践基地平面图 424→407、酒店疏散图 318→302），
**没有任何一处把题干吸进图里**。

### 12.4 限量改成"先挑大的，再排阅读顺序"

`MAX_PER_QUESTION` 原来按 y 截断，真实后果：第三单元练习题第 5 题的 **453×109 大图
被三个 58×46 小方块挤掉**。现在按面积挑前 N，再按 y 排序输出；上限 3→4 实测
图数 +3、打印页数一张没变。

## 13. 第八轮：把九份真卷逐页重做一遍（"你能做完才算没问题"）

### 13.1 这一轮的验收口径换了

前七轮都是"我认为哪里不对 → 修 → 跑单测"。这一轮总裁把口径换成两条硬的：

1. **"你把应该一页的弄成多页了"** —— 一张图不许切成几块，一份卷子不许被图撑胖；
2. **"你把试卷截出来自己再做一遍，用大模型看看还全不全，反复优化到所有题能正常"**；
3. **"把我的资料 E:\<真卷目录> 全部测一遍，保证生成的题你自己可以重新做完，才算没有问题。"**

所以这一轮不再靠人眼挑一条改一条，而是先做一把**能自己喊"做不了"的尺**，
让它去量本地真卷目录（不入库）全部 9 份材料（3 份照片 + 6 份扫描/文字 PDF，共 24 页源页）。

### 13.4 这一轮真正改掉的十条判据

1. **题号被 OCR 单独切成一行 → 整道题凭空消失**（第三单元练习题 第 4 天 第 3 题）。
   现象：题号"3"印在图顶上（y=450），题干"观察图片，提出两个能用6×2解决的问题。"
   印在图底下（y=570），中间隔着整张图。`Q_NUM_RE` 要求题号后面有顿号/点，
   裸一个"3"不认 → 这道题被并进上一题。
   修法：`rules._bare_number_starts_question()` —— 整行只有一个数字时，
   **必须同时满足**"正好等于上一题号 +1""上一题已经有 ≥4 字题干""本大题已有带号题"
   三条才开题（挡掉图里孤立的数字、统计图上的 1 2 3 刻度、大题开头的裸数字）。
   配套：`lines.spans_for_questions.anchor_row()` 把裁图区间的**起点抬到那一行题号**，
   否则整张图还是落在上一题的区间里（反例：那行的数字和本题题号对不上时一律不抬）。

2. **（1）（2）小问被切成两道大题 → 卷面出现重号假题**（达标练习题A 第三大题）。
   修法：`extract()` 里新增"小问并回上一题"分支，**只有上一题是"1."这种平排题号**时才并
   —— 整段都用（1）（2）编号的卷（"选一选。（1）…（2）…"）它们就是平级题目，不许并。

3. **题干和图注被 OCR 并成一行 → 图注被挖掉，题做不了**
   （综合实践单元(1) 第 4 题：`"4.如右图所示，两名同学玩背靠背夹    我面向东。"` 是一行）。
   整行挖掉＝气泡"我面向东。"从图里消失（不知道谁面向东，这题无解）；
   整行吸回＝题干进图（用户上一轮骂过的"图片和题目不对应"）。两头都错。
   修法：`figures._row_fragments()` 先按行内 ≥6pt 的空白把这一行切成碎片，
   只吸**贴着图边、宽度 16–45pt、且这一侧还没吸过**的那一片；
   页脚/页码那种"印刷家具"行永远不当图注（`is_furniture_text`）。
   结果：那道题的图从"两个小孩没有气泡"变成"气泡 + 两个小孩 + 乐乐/龙龙"，能做。

4. **小版面的真图被"太小不值得裁"砍没**（综合实践单元(1) 整页只有 370×287pt，
   一栏 192pt，同一张插图只有 53×22pt，而门槛是在 A4 栏（≈280pt）上量的）。
   修法：`_gate_scale(col_w)` —— 尺寸/墨量门槛按**栏宽**缩放，
   **只放宽不收紧**（scale ≤ 1，下限 0.5）；并且放宽那一档**只在这道题一张严格合格的图
   都没有时才生效**（`_prefer_strict`），否则小版面会把装订线碎墨、页脚那行字一起放进来。

5. **跨题缝合把上下两张不相干的图缝成一张**（记录单 148pt 宽，压在它下面的小孩图 59pt 宽）。
   修法：`STITCH_MIN_W_RATIO = 0.6` —— 两半宽度比值不够就不缝（正例围棋盘是 127/130）。

6. **缝合后无脑挂"靠前那道题" → 图落在第 4 题区间里更多，却挂给了第 3 题**
   （综合实践单元.pdf 第 1 页，第 4 题"如右图所示"因此一张图都没有）。
   修法：`_band_share()` —— 拼出来的图挂在**它落在谁区间里更多**的那道题上，一样多才退回"靠前"。

7. **页脚 + 扫描 app 的 logo 被缝进题图**（综合实践单元(1) 第 2 页 书法馆路线图，
   成品图上印着"夸克扫描王"和它的二维码）。
   根因两层：① 页脚那行字被挖掉后，补洞合并认为"这道缝是我们自己挖的"→ 缝过去了；
   ② 膨胀半径 7pt 又把图和页底下的 logo 接成一个连通域。
   修法：`is_furniture_text()`（页码/第N页/共N页/扫描app品牌词）占的行
   **不算洞、算墙**：不进 `hole`（补洞不跨）、在膨胀之后从掩码里抹掉（连通域不跨）、
   并且永远不当"图注"被吸回。

8. **"圈小标点"把换行正文一路串进裁图**（小版面一栏的换行正文只有 86pt 宽，
   照样过"宽度 ≤ 90pt"那道关，于是"的口令后，同学们将面向（ ）站立。"和页脚
   "157 综合实践(一)达标练习…"被串成一张 123×38 的"题干图"）。
   修法：`SHORT_MARK_TEXT_RE` —— 圈进来之前先看内容，**只有标点/括号/空白**才算小标点。

9. **带题号的行被当"卷首信息行"丢掉**（`HEADER_HINTS` 里有"答案"，
   于是"1. 看图填方向，把答案写在括号里。"整行进 `skipped`，卷面少一道第 1 题）。
   修法：`_looks_like_header()` 先排除 `Q_NUM_RE`/`Q_CIRCLED_RE` 命中的行。

10. **页脚"共 N 页"和真实页数不一致**（九份卷全部命中：页脚写"共 4 页"，PDF 实际 5 页）。
    根因：数页数那一趟没传 `fig_dir` → 配图被跳过 → 版面偏短 → 页数少算。
    修法：第一趟也带 `fig_dir`；测试 `footer_page_total_matches_when_figures_take_space`
    把每页页脚的"共 N 页"读回来和 `page_count` 对。

### 13.5 这一轮也打坏了两把"看着在量其实没量"的尺

* **变异闸门本身会漏报**。`tests/mutate_gate.py` 改坏源码 → 跑测试 → 还原，
  三步常常落在**同一秒**内，而 Python 的 `.pyc` 失效判定就是"源文件 mtime(秒) + 大小"，
  于是子进程拿到上一次那份 `.pyc`，跑的是**没被改坏**的代码 → 判成"这条缺陷没有尺在量"。
  同一份变异表两次跑出 20/20 和 25/27 就是它。修法：跑子进程一律 `-B`（不写字节码）
  + 动手前先把被改模块的 `__pycache__` 清掉。修完 **29/29、34/34 稳定全抓到**。
* **切边尺把邻题的图算成"这道题被切掉一块"**。两张图上下紧挨着时（周末作业两幅格子图、
  综合实践单元 记录单和小孩图），下一张图的墨正好贴在上一张裁框外面。
  修法：量外边带之前先把**别的题已经裁走的框**挖掉；
  这条改动本身也配了正/反对照（不挖 → 该报；挖了 → 不许报），写在 `selftest()` 里。
  九份卷的"切边"从 9 条降到 4 条，剩下 4 条是真贴边墨（照片卷的图没有边框线）。

## 14. 第十轮：小问要分开作答 + 画出来的图形必须读得出来

用户这两句话是本轮的全部需求，都是拿真卷截图指着说的：

> "这个一个题目里面有三个小题，不能分为独立的三个小题吗？非得挤在一个框子里，怎么分别作答呢？"
> "你这个题目就不全啊，至少简单的 ⭐ □ 这种图形你得支持啊，要不然题目都不全，你写的东西别人都看不懂是要干啥。"

### 14.1 小问（1）（2）（3）：分行分空，但仍是一道题

拆成三道独立题会重排题号、丢分值（上一轮就是这么造出"重号假题"的），
所以口径定成：**题号/分值/批改按一道题走，排版和作答按小问走**。

* `rules.split_subqs(text)` → `[{no, text, blanks, lead}]`。四条判据各挡一类误伤：
  括号里必须是**正好一个数字**（空位写作"（   ）"没有数字，永远不会被当小问号）、
  编号必须**从 1 严格递增**（"3×4=（12）"这种填了数的不算）、
  **至少两段且每段非空**（光杆"（1）（2）（3）"拆出来是三个空行，不如不拆）、
  第一个小问之前的**引导语**单独留成 `lead`（"看图填一填。"不是小问，也不能丢）。
* `db.get_questions()` 读时挂 `subqs` 视图，不存第二份真相：家长改了题干，
  下次读出来就跟着变。
* 打印版每问各起一行（`answer_writer`）；做题页空位标签按问分组
  （`(1)第1空 / (1)第2空 / (2)第1空…`）；校对页挂"小问 N 项"徽标。
* 判据只实现一份：`blankLabels` / `stemLines` 搬进 `web/js/subqs.js`（纯函数、不碰 DOM），
  所以能被 node 直接跑 —— 内联在 HTML 里的逻辑只有"打开浏览器才知道对不对"，那不算有尺。
* 真卷效果（`第三单元练习题.pdf` 第 1 页第 2 题，库里那份直接渲染）：

  ```
  2. （1）2只2只地数,数了(      )次,一共有(      )只蝴蝶。
     （2）3只3只地数,数了（      )次,一共有(      )只蝴蝶。
     （3）4只4只地数,数了(      )次,一共有(       )只蝴蝶。
  ```
  这份卷 37 题里 6 题切出了小问（含"小兔子吃胡萝卜。"这类引导语两题）。

### 14.2 空位数：括号里的长空格流以前根本不算空位

`BLANK_RE` 旧写法是 `（\s{0,4}）|\(\s{1,4}\)`，只认 1–4 个空格。
真卷扫描后 OCR 把空位读成 **6–8 个空格**：这份卷卷面 33 个空位，系统只数到 **3 个**
（读数表：含括号宽度 3–10 字符，出现次数 `{3:1, 6:1, 7:5, 8:18, 9:6, 10:2}`）。
这就是"没法分别作答"的另一半根因——**输入框数量压根不对**。

* 改成括号内空白不限长度：括号里全是空白就是空位，没有第二种解释；
  填了内容的"（ 12 ）"、带字的"（ 见上图 ）"照样不算（三个反例在测试里）。
* 空位数改成**读时派生**（和小问同一套原则），老库不用重新上传就自愈。
* 前端 `proofread.html` 自己那份 `/{0,6}/` 口径删掉，改调 `PJSubs.countBlanks`；
  `tests/cross_blanks.js` 拿 Python 侧持有的同一批字符串两边各数一遍比对
  （13 条 / 14 个空位）。**清单只许有一份**——两处各抄一份，漂了都不知道比的是不是同一批。

### 14.3 画出来的图形符号：★＋★＝20 现在读得出来

这份材料是**纯扫描件**（8 页，每页文字层 0 字符），星星月亮是像素，OCR 只认字，
于是整行只剩"=20 39"。新增 `app/extractor/symbols.py`：在**已经挖掉 OCR 文字行**的墨里
（复用 `figures._scan` 那一份中间量，不另抄一遍），把"一个字符那么大的一坨"按轮廓分类，
再和 OCR 碎片按 x 拼回这一行。

* 判据全部来自真卷读数表（27 个小块的实心度/圆度/顶点/填充率）：
  圆润星 sol 0.83 cir 0.62，尖角星 sol 0.50 → 所以星形靠**径向外凸数（几个角）**判，
  不靠胖瘦；括号靠"又高又窄 + 外轮廓不凸"判，开口方向看**顶端 x − 中段 x**
  （质心偏移会被线宽带偏，实测翻过一次）；正方形和菱形只有**顶边满不满宽**分得开；
  ＋ 和 × 只有**顶行一段还是两段**分得开；"＝"在扫描图上是两根独立扁杠，必须折叠，
  否则"★＋★＝20"会印成"★＋★－－20"——**一道错的算式比读不出更糟**。
* 只用打印字体里真有字形的字符（simhei/msyh 有 ★●○□△▲◇◆〔〕＝＋×－÷（），
  **没有 ⭐🌙 这类 emoji**，写 emoji 在家长的 PDF 里就是空白方块）。
  认不准的弯月/花朵一律标 `〔图〕`，不冒充具体形状。
* 行闸门四条，缺一条就印出鬼话（都是九份真卷全量跑出来的）：
  ① ≥2 个形状；② 必须带运算符；③ 行内必须有等号（图形算出来的 ＝ 或 OCR 读到的 =）
  —— 没有这条，"数一数"的圆点阵、"连一连"的箭头堆、扫描 app 的 logo
  （一个圆 + 两个方块）都会被拼成一行算式；④ 行里有中文说明就放弃（图形属于旁边的图）；
  另有一条硬规矩：**一个小块认不出来，整行放弃**，绝不半拼。
* 九份真卷全量跑的落地结果：只有《第三单元练习题》2 道题还原出算式，其余 8 份 0 行
  （宁缺毋滥的口径就是这个数字）：

  ```
  第 4 题  ★＋★＋★＋★ =20
           ★＋★＋〔图〕＋〔图〕＋★＋★＋★＝39
  第 5 题  □×□＝□ □×□＝□ □×□＝□
  ```
* 还原的行**单独存 `symbols` 一列、单独一块显示**（校对页/做题页/打印版都标
  "按卷面图形还原，非卷面原文"），不并进题干：家长必须分得清哪半句是读到的、
  哪半句是系统拼的。

### 14.4 裁图被从中间截断：同行被砍的小块要并回来

第 4 题的裁框停在 x=407.6，式子末尾的"（   ）"在 x=434（11×22pt，被 `small` 闸门单独砍掉），

### 14.7 校对页要能自己打数学符号

  变成"×÷"就等于改不动。优先用浏览器原生插入（保留撤销栈），不支持时回落到改值＋补发 `input`。

### 14.9 自己对照源卷才找到的那条：题号粘在题干行首 → 图整个给上一题

他第三次开火："**你能不能自己对照一下，这题都对不上，怎么做啊**"。
审计尺报"做不了 0"，可题是错的 —— 说明形式化的尺看不见"图挂错题"这一类。
于是把源卷每一题那一块和系统做出来的东西并排拼成对照表（37 题 / 19 张图）逐张看，
第 2 页立刻露馅：

* 第3题的裁框 `[53, 437, 562, 588]` 里既有该它的三个树叶选项框，
  也有第4题的"4.(1)一共有多少根胡萝卜?"、答题空 `□×□=□( )` 和货架图；
* 第4题"**成品配图 0 张**"。

根因在 `lines.spans_for_questions` 的 `locate`：第4题第一行在源卷上是
**`4.(1)一共有多少根胡萝卜?`**（题号和小问序号粘在同一行）。
匹配两边都先剥编号，可**行剥掉 `4.` 还剩 `(1)`、题干剥掉的正是 `(1)`，
剥的层数不一样** → 这一行没被认成第4题的起手行 → 第4题的区间从第二行
`(2)5X2…` 才开始 → 中间 65pt（算式空 + 货架图）整个落进第3题的区间。

修法：`locate` 加第三种匹配 —— **行首正好是本题题号**时，把那一层剥掉再比。
只认本题题号那一种粘法（别的数字前缀不算，否则等于把区间起点随便往上挪）。
真卷结果：


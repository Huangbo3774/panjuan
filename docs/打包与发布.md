# 打包与发布（免安装版）

这份文档回答一个问题：**怎么让一个不懂命令行的家长用上磐卷。**
答案不是"教他装 Python"，是把 Python 藏进产物里：下载 zip → 解压 → 双击 `PaperForge.exe`。

---

## 一条前提：架构不变

打包**没有**改变产品形态，还是"本机服务 + 浏览器"：

- 不联网、不上传、无账号（隐私口径与 README 完全一致，`/api/health` 里也会自报 `frozen: true`
  和数据落在哪个目录，验收脚本会把它打出来）；
- exe 里跑的就是仓库里那份 FastAPI 应用，**没有第二套代码**要维护；
- 关掉那个黑框 = 停止服务。黑框不是"卡住了"，它就是程序本身。

代价只有一个：**体积**（含 OpenCV + onnxruntime + OCR 模型，见下面的实测）。

## 为什么 onedir 而不是 onefile

onefile 每次启动都要把整个归档解到 `%TEMP%`——我们这套几百 MB，
冷启动要多等几十秒，而且解出来的临时目录是杀软最爱盯的东西。
onedir 是"解压一次、以后直接跑"，双击秒开；反正发的是 zip，用户本来就要解压，
多一个 `_internal` 文件夹对他没有区别。

## 怎么构建（开发者侧）

```powershell
.\scripts\build_exe.ps1            # 建干净 venv + 装依赖 + 打包 + 压 zip
.\scripts\build_exe.ps1 -SkipVenv  # 沿用已就绪的 .venv-build，只重新打包
.\scripts\build_exe.ps1 -Clean     # 先清 build/ 与 dist/
```

产物：

```
dist\PaperForge\                  免安装版整个文件夹（可以直接拷给别人）
 ├─ PaperForge.exe                双击它
 ├─ _internal\                    Python 运行时 + 依赖 + web 前端 + OCR 模型
 ├─ data\                         试卷库（题目、标准答案、作答记录）
 ├─ var\                          临时目录，每次启动清空
 └─ 使用说明.txt
dist\磐卷-Windows-免安装.zip       挂到 GitHub Release 的那个文件
```

**必须在干净 venv 里构建**（脚本自动建 `.venv-build`）。开发机上的全局 Python 里躺着
1.8GB 无关包（polars / playwright / gradio / streamlit / scipy…），PyInstaller 顺着
import 抓，环境越脏越容易把不该带的拽进来；而且"我这台机能打包"和"clone 下来也能打包"
会变成两回事。这条不是洁癖：`python-multipart`（上传接口必需）以前就是靠别的包蹭进来的，
requirements.txt 里根本没写，干净环境一装就 500。

## 打完必须做的验证（不验就等于没打）

`exe 能双击` 不算交付。要对**产物**跑同一套验收：

```powershell
# 1) 起 exe（--no-browser 免得弹浏览器；端口换成 8100 避开开发用的 8000）
Start-Process dist\PaperForge\PaperForge.exe -ArgumentList '--no-browser','--port','8100'
# 2) 让验收打这个外部服务，而不是自己 import 源码起一个
$env:PJ_BASE = 'http://127.0.0.1:8100'
py -3.11 tests\acceptance_v11.py        # V1.1 十条（含 OCR 配图、A3 对开、三态导出）
py -3.11 tests\acceptance.py            # V1.0 十一条（含 100 页压力，量的是 exe 进程内存）
```

外部模式下验收会**原样打印远端自报的 `pid / frozen / build / 数据目录`**，
并要求你确认"这就是我要测的那一份"——因为这时没法再像自起模式那样核对
"回答我的是不是我刚生的那个进程"，而"测了旧代码却报全绿"这个坑本项目踩过。

重点看这几条，它们是打包最容易静默坏掉的地方：

| 验的东西 | 坏掉时的表现 |
|---|---|
| OCR 模型真被打进去 | 扫描卷**一道题都认不出来**，但不报错 |
| `web/` 进了 `_internal` | 页面 404 或空白 |
| uvicorn 的 loops/protocols | 起得来，第一个请求就 ImportError |
| 中文字体 | 非中文 Windows 上回退 CID 字体，PDF 仍能出（横幅会写用的是哪个） |
| 数据目录可写 | 被放进只读位置时回退到 `%LOCALAPPDATA%\PaperForge`，横幅会说明 |

## 发布侧的三件事

1. **GitHub Release 资产名必须是纯 ASCII**。2026-10-19 发 v1.1.0 时踩实了：
   README 原来写 `磐卷-Windows-免安装.zip`，`gh release create` 传上去后
   附件被 GitHub 折成 `-Windows-.zip`（**资产名进 URL，只认 ASCII**，中文只能放 label）。
   现在线上附件叫 `panjuan-v1.1.0-windows.zip`，label 是「磐卷 免安装版（Windows）」，
   中英 README 的下载名跟着改成同一个 ASCII 名。
   闸门：`tests/check_release_names.py`（check.bat 第 18 步）——
   README 里出现的 `.zip` 名字含非 ASCII、或中英两份不一致，直接 FAIL。
   本地构建产物仍叫 `dist\磐卷-Windows-免安装.zip`（那是自己机器上的文件，不进 URL）。
2. **SmartScreen**：未做付费代码签名的 exe 第一次运行会弹"Windows 已保护你的电脑"，
   需要点「更多信息 → 仍要运行」。`使用说明.txt` 里写了这段话。
   买证书（OV/EV，年费量级）能消掉它，但那是另一笔开销，当前不做。
3. **UPX 一律关**（spec 里写死 `upx=False`）：UPX 压过的 exe 是杀软误报的头号来源，
   公开下载的产品不给自己添这个麻烦。

## 打包这一轮暴露并修掉的三个真 bug

都不是"打包特有问题"，是**只有干净环境 + 真跑一遍才会露出来**的：

1. **`/api/health` 直接 500**：路径收口时把 `APP_HOME` 导入成了 `ROOT`，health 里还引用原名。
   65 条单元测试全绿也拦不住它——没有一条打健康检查。是 `check.bat` 第 14 步（走真实 HTTP 的验收）抓的。
2. **`entry.py` 里用了 `json` 却没在顶部 import**：异常被自己写的 `except Exception` 吞掉，
   于是"端口上就是磐卷"被误判成"陌生程序占端口"。修完三条分支（已在跑 / 陌生端口 / 空端口）逐条实测过。
3. **横幅里的 `✗` 在输出被重定向时崩**（`UnicodeEncodeError: gbk`）：Python 只在 stdout 真连着控制台时
   走 UTF-8，一旦是管道/重定向就退回 cp936。现在入口第一件事就是 `reconfigure(encoding="utf-8")`。

另外补了 **`python-multipart` 进 requirements.txt**：上传接口必需，以前靠这台机上别的包蹭进来，
干净 venv 一装就暴露——"代码里用到的东西必须写在自己的清单上"。

## 已知代价（说在前面）

- **126 MB 的下载包**：换来的是对方零安装。要更小就得砍掉 OpenCV/OCR，那等于砍掉"手机拍的照片也能出卷"这个主场景。
- **未做代码签名**：第一次运行 Windows 会弹 SmartScreen，要点「更多信息 → 仍要运行」。证书是年费开销，当前不做。
- **只打了 Windows x64**：目标用户（家长）几乎全是 Windows。macOS/Linux 走源码路径。
